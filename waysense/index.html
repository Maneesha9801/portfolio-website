The Design Problem

GPS fails indoors. For large complexes like malls or multi-level parking lots, this creates a "last-mile" navigation gap. Users can drive to the mall, but they can't find their way inside it.

Existing solutions like BLE Beacons require installing thousands of battery-powered devices (high maintenance). LiDAR/Camera systems are privacy-invasive and computationally expensive.

"How might we build a navigation system that requires ZERO new hardware installation?"

The Engineering Logic

Decision A: Accessibility over Precision

We initially considered Wi-Fi RTT (Round Trip Time), which offers 1-meter precision. However, it requires Android 9+ and specific router hardware.

Instead, we chose RSSI Fingerprinting. It works on almost every smartphone and uses standard Wi-Fi Access Points. The trade-off? Lower precision (~5m). But for a car in a parking lot, 5m is acceptable.

Decision B: The 2.4GHz vs 5GHz Spectrum

5GHz signals are easily blocked by walls (high attenuation). 2.4GHz signals penetrate walls but are noisy. We built a hybrid scanner that prioritizes 5GHz for "Room Detection" (strong signal = definitely in this room) and 2.4GHz for "General Vicinity" (weak signal = somewhere nearby).

The Digital Twin Approach

We couldn't just "triangulate" because indoor signals bounce (multipath effect). Instead, we created a Digital Twin of the building's signal landscape.

Intervention A: The Heatmap Database

We divided the floor plan into a grid. At each grid point, we recorded the signal strength (RSSI) from all visible Access Points. This created a unique "fingerprint" for every 2-meter square.

Intervention B: The "Handover" Algorithm

As a user moves, their phone's observed signal vector changes. We used K-Nearest Neighbors (KNN) to match the live vector against our database. To prevent "jumping" between floors, we added a Hysteresis Filter—the system only changes floors if 5 consecutive scans confirm the new location.

Validation & Impact

  • Accuracy: Achieved 92% accuracy in room-level detection within the Computer Science block.
  • Latency: Position updates every 1.5 seconds, sufficient for walking speed.
  • Cost: $0 hardware cost. Deployed using only existing university routers.
